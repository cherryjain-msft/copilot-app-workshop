    Lesson 1 - Meet the Copilot app

    ⏱ 10 minCopilot app

    Tour the desktop command center for agents, then run two sessions side by side.

    In this lesson, you will:

    • find your way around the sidebar and the session view.
    • start a local session and choose a mode.
    • run a second session in the cloud at the same time.

    Take the tour

    AreaWhat it's for
    SessionsEach session is one agent on one task. Local sessions get their own git worktree and branch, so agents don't trip over each other.
    ProjectsGroup sessions, files and automations around one goal. You'll create one in lesson 2.
    ChatsConversations that don't need a repository checkout.
    AutomationsAgents that run on a schedule, on GitHub events or on demand. See lesson 9.
    CustomizeConnectors (MCP servers), skills, custom agents and canvases.
    Right-side panelThe session's Changes, the plan, the pull request and any open canvases.

    Start your first session

    1. Start a new session on the repository.
    2. Keep it local with a new worktree.
    3. Set the mode to Interactive and the model to Auto.
    4. Send this prompt: 
      Explain this repository in five bullets for a new developer, then list the API endpoints.
    5. When it finishes, run: 
      !git status

    You should see a short summary that lists GET /api/services, GET /api/slots and POST /api/bookings, and git status should show the session's own branch.

    Choose a mode

    ModeWhat it doesUse it for
    InteractiveWorks with you step by step and asks before risky actions.Exploring and learning a codebase.
    PlanWrites a plan first. You edit and approve it before any code changes.Features like FORD-101.
    AutopilotKeeps going until the task is done without stopping for approval.Well-scoped tasks and automations.

    Run a cloud session in parallel

    1. While the first session runs, start a second session and choose cloud as the place it runs.
    2. Send this prompt: 
      Add JSDoc comments to every exported function in app/src/bookings.js. Don't change any behavior.
    3. Watch both sessions in the sidebar. Each one shows whether it's working, waiting for you or done.
    Note

    Cloud sessions keep running when your laptop is closed, but connectors you signed in to in the app, like Jira and Figma, aren't available there. Run lessons 3, 6 and 7 in local sessions.

    "One app, many agents, each in its own worktree. You stay the reviewer."

    The Copilot app has been generally available since June 17, 2026, on macOS, Windows and Linux.

    Summary and next steps

    You toured the app, ran a local session in its own worktree and started a cloud session in parallel. Next, you'll set up a Project for the FORD sprint.

    Lesson 5 of 10

    Lesson 5 - Copilot Fusion

    ⏱ 10 minCopilot Fusion

    You choose an effort level, not a model. Fusion picks and combines models for the task.

    In this lesson, you will:

    • learn the three Fusion effort levels and how they work.
    • run a quick task on Standard and a review on High.
    • compare High, Max and a single model side by side.

    Pick an effort level

    EffortHow it worksUse it for
    StandardSingle: routes the task to one well-suited model.Everyday edits, docs and questions.
    HighCascade: an efficient model drafts and a judge model accepts or escalates.Features, reviews and multi-file changes.
    MaxCritique: several critics review the draft in parallel and the drafter revises.Hard bugs, risky changes and design decisions.

    Try Standard

    1. In the model picker, choose Copilot Fusion and set the effort to Standard.
    2. Send: 
      Write a JSDoc comment for the isValidDate function in app/src/slots.js.

    Try High

    1. Switch the effort to High and send: 
      Review app/src/bookings.js and app/src/server.js for edge cases in booking validation and concurrency. List the top 3 risks with a test idea for each. Don't change any files.
    2. Hover over the effort label on the response to see which models ran.

    Expect risks such as bookings in the past, no length limit on customerName, and bookings lost on restart because the store is in memory.

    Important

    Stay the reviewer. If Copilot reports a race condition in create(), push back: the method is synchronous, so two requests can't interleave inside it in Node.js.

    Compare side by side

    Start three sessions with the same prompt: one on Fusion High, one on Fusion Max and one on a single model, for example Claude Opus 5.5.

    Propose the smallest safe change to block bookings in the past, with the test. Don't edit files; show the diff.

    Compare the quality, the time taken and the credits each one used.

    Note

    Fusion only uses models your organization's policy allows. If Max isn't offered, a required model is turned off by policy, so use High.

    Copilot Fusion is generally available since October 28, 2026, in VS Code, the Copilot CLI, the Copilot app and JetBrains IDEs.

    There's no separate fee. High and Max can use more credits than Standard. Paid plans get 30% off Fusion through November 30, 2026.

    Fusion Max scored 60 on the Artificial Analysis Coding Agent Index, within 2 points of the top entry, at about half the cost and about 40% less time.

    Admins can exclude models from Fusion or make Fusion the default.

    Summary and next steps

    You used Standard for a quick task, High for a review and compared High, Max and a single model. Next, you'll open the Jira Sprint Workbench.

    ⏱ 15 minCustom canvasLocal session

    A project canvas that turns your sprint into a dashboard and walks each story through five gated stages, with Jira kept up to date.

    In this lesson, you will:

    • start a story with Copilot from the dashboard.
    • run the five workflow stages and post results to Jira.
    • update the story's status and fields without leaving the app.

    Open the sprint dashboard

    The extension ships with this repository in .github/extensions/jira-sprint-workbench/, so it loads automatically. You need the Atlassian connector from lesson 3.

    Open the jira-sprint-workbench canvas for my Jira site.

    Copilot looks up your site's cloudId and siteUrl and opens the dashboard.

    Jira Sprint Workbench FORD · active sprint
    8 Total scope · 1 Done · 2 In progress · 1 Needs attention
    FORD-101 Reserve an EV charging bay during serviceOpen workbench Start with Copilot
    FORD-102 Show the service duration on each slotOpen workbench Start with Copilot

    Start a story

    1. On FORD-101, select Start with Copilot. The workbench creates a nested Autopilot session for the story, and the button changes to Open session.
    2. Select Open workbench to open the story panel.

    Run the workflow

    Under Copilot workflow, each stage unlocks when the one before it is done. Run sends a prompt to the session, and the agent reports back with record_stage_result, so the panel updates live.

    #StageWhat happens
    1Analyze with codebaseMaps the acceptance criteria to code, risks and open questions.
    2Plan & create GitHub issuesCreates one or more GitHub issues labeled jira:FORD-101.
    3Implement with Copilot coding agentAssigns the issues to @copilot, which works in the cloud.
    4Test cases & coverageMarks each case covered, partial or missing. Add missing tests fills the gaps.
    5Pull request & code reviewCreates or confirms the PR, requests a Copilot review and reports findings. It never merges.

    Keep Jira up to date

    Each stage card has a checkbox to post to Jira automatically when the stage succeeds. Failed stages are never posted.

    To post by hand, open Update Jira under a stage, edit the text and select Post comment to Jira.

    Move to In Progress on the Implement card moves the story when the coding agent starts.

    On approve, move to on the Review card moves the story when the review has no blocking findings.

    In Update issue, change the status, summary, priority, labels or description, then select Save changes. Only the fields you changed are sent.

    Note

    The workbench saves its state in ~/.copilot/jira-story-workbench/<cloudId>.json. Jira is only written when a box is checked or you select a button.

    "Jira stays the system of record. The app does the work, and the story shows what happened at each step."

    The workbench is Apache-2.0 and based on the Atlassian Labs jira-sprint-dashboard-canvas.

    Lesson 8 - Review loop and Agent Merge

    ⏱ 10 minCode reviewAgent Merge

    Get a Copilot review, apply the fixes, and let Agent Merge take the pull request over the line.

    In this lesson, you will:

    • request a Copilot code review and fix the findings.
    • hand the pull request to Agent Merge.
    • learn how stacked pull requests and evidence attachments work.

    Request a Copilot review

    1. In the session, open the Changes tab for the FORD-101 pull request.
    2. Under Reviewers, add Copilot.
    3. When comments arrive, select Fix on a comment to send it back to the session, or ask: 
      Address the Copilot review comments on this pull request, run npm test in app/, and push the fixes.

    Hand off to Agent Merge

    Turn on Agent Merge for the pull request. It addresses review comments, fixes failing checks, resolves merge conflicts and merges when everything is green.

    Important

    Agent Merge follows your branch protection rules. Required reviews and required checks still apply.

    Go further

    Split a large change into small pull requests that build on each other:

    gh stack init fix/ev-slots-api
gh stack add -Am "Add EV charging to the booking UI" fix/ev-booking-ui
gh stack submit --auto

    Attach screenshots to a pull request or issue from the command line:

    gh pr create --title "FORD-101: Reserve an EV charging bay" --body "See the screenshot." --attach 'evidence/after.png#EV charging panel on the booking page'
gh issue comment 12 --attach 'evidence/after.png#EV charging panel'

    "The agent wrote it, another agent reviewed it, and your rules still decide when it merges."

    You reviewed the pull request with Copilot, applied fixes and handed off to Agent Merge. Next, you'll automate this whole flow.

    Cloud · Shared · GitHub event triggers

    1. Select New automation, then Create manually. Name it PR standards check and turn on Run in the cloud.
    2. Triggers: Pull request opened and Pull request ready for review.
    3. Can be triggered by: People and Copilot. Can change: Only the triggering issue.
    4. Tools: Read pull request, Read files, Add pull request review comment, Add pull request comment.
    5. Model: Copilot Fusion · High. Credits: 100 per run, 500 per day.
    6. Paste the prompt: 
      Review this pull request against our team checklist in .github/pr-checklist.md.

1. Read the checklist and the PR diff.
2. Post ONE summary comment on the PR with a table:
   checklist item | pass / fail / n/a | evidence (file:line or short reason)
3. For each failed item, add an inline review comment on the relevant line with a concrete suggested fix (use a suggestion block when the fix is small).
4. End the summary with "Ready to merge" or "Changes requested: <count>".

Be specific and brief. Do not push commits, approve, or merge.
    Tip

    To test it now, select Run, choose the Pull request opened trigger and paste the FORD-101 pull request URL as the Resource URL.

    Local · Weekly, Friday 15:00

    1. Select New automation. Name it Sprint digest.
    2. Set the schedule to Weekly, Friday at 15:00, and the model to Copilot Fusion · Standard.
    3. Paste the prompt: 
      Build this week's sprint digest for the FORD Jira project.

1. Using the Atlassian connector, find issues in the FORD project in the open sprint.
2. Group them by status: Done this week, In progress, In review, Blocked, Not started.
3. In this GitHub repository, create an issue titled "Sprint digest – week of <Monday's date>" with:
   - a 3-bullet executive summary (progress, risks, asks)
   - a table per status group: Jira key (linked) | summary | assignee | linked GitHub PR (if any)
4. Flag anything In progress for more than 5 days as a risk.

Do not change anything in Jira.
    Note

    To run it in the cloud instead, add the Atlassian MCP server in the repository's Copilot → MCP settings and set limits such as 60 credits per run and 400 per month.
