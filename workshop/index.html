    Lesson 1 - Meet the Copilot app

    ⏱ 10 minCopilot app

    Tour the desktop command center for agents, then run two sessions side by side.

    In this lesson, you will:

    • find your way around the sidebar and the session view.
    • start a local session and choose a mode.
    • run a second session in the cloud at the same time.

    Take the tour

    AreaWhat it's for
    SessionsEach session is one agent on one task. Local sessions get their own git worktree and branch, so agents don't trip over each other.
    ProjectsGroup sessions, files and automations around one goal. You'll create one in lesson 2.
    ChatsConversations that don't need a repository checkout.
    AutomationsAgents that run on a schedule, on GitHub events or on demand. See lesson 9.
    CustomizeConnectors (MCP servers), skills, custom agents and canvases.
    Right-side panelThe session's Changes, the plan, the pull request and any open canvases.

    Start your first session

    1. Start a new session on the repository.
    2. Keep it local with a new worktree.
    3. Set the mode to Interactive and the model to Auto.
    4. Send this prompt: 
      Explain this repository in five bullets for a new developer, then list the API endpoints.
    5. When it finishes, run: 
      !git status

    You should see a short summary that lists GET /api/services, GET /api/slots and POST /api/bookings, and git status should show the session's own branch.

    Choose a mode

    ModeWhat it doesUse it for
    InteractiveWorks with you step by step and asks before risky actions.Exploring and learning a codebase.
    PlanWrites a plan first. You edit and approve it before any code changes.Features like FORD-101.
    AutopilotKeeps going until the task is done without stopping for approval.Well-scoped tasks and automations.

    Run a cloud session in parallel

    1. While the first session runs, start a second session and choose cloud as the place it runs.
    2. Send this prompt: 
      Add JSDoc comments to every exported function in app/src/bookings.js. Don't change any behavior.
    3. Watch both sessions in the sidebar. Each one shows whether it's working, waiting for you or done.
    Note

    Cloud sessions keep running when your laptop is closed, but they do not automatically inherit connectors you signed in to in the app. Keep Jira and Figma reads in the local delivery session. In lessons 6–7, put the approved requirements and design details in the GitHub issue before handing it to the cloud coding agent.

    "One app, many agents, each in its own worktree. You stay the reviewer."

    The Copilot app has been generally available since June 17, 2026, on macOS, Windows and Linux.

    Lesson 5 of 10

    Lesson 5 - Copilot Fusion

    ⏱ 10 minCopilot Fusion

    You choose an effort level, not a model. Fusion picks and combines models for the task.

    In this lesson, you will:

    • learn the three Fusion effort levels and how they work.
    • run a quick task on Standard and a review on High.
    • compare High, Max and a single model side by side.

    Pick an effort level

    EffortHow it worksUse it for
    StandardSingle: routes the task to one well-suited model.Everyday edits, docs and questions.
    HighCascade: an efficient model drafts and a judge model accepts or escalates.Features, reviews and multi-file changes.
    MaxCritique: several critics review the draft in parallel and the drafter revises.Hard bugs, risky changes and design decisions.

    Try Standard

    1. In the model picker, choose Copilot Fusion and set the effort to Standard.
    2. Send: 
      Write a JSDoc comment for the isValidDate function in app/src/slots.js.

    Try High

    1. Switch the effort to High and send: 
      Review app/src/bookings.js and app/src/server.js for edge cases in booking validation and concurrency. List the top 3 risks with a test idea for each. Don't change any files.
    2. Hover over the effort label on the response to see which models ran.

    Expect risks such as bookings in the past, no length limit on customerName, and bookings lost on restart because the store is in memory.

    Important

    Stay the reviewer. If Copilot reports a race condition in create(), push back: the method is synchronous, so two requests can't interleave inside it in Node.js.

    Compare side by side

    Start three sessions with the same prompt: one on Fusion High, one on Fusion Max and one on a single model, for example Claude Opus 5.5.

    Propose the smallest safe change to block bookings in the past, with the test. Don't edit files; show the diff.

    Compare the quality, the time taken and the credits each one used.

    Note

    Fusion only uses models your organization's policy allows. If Max isn't offered, a required model is turned off by policy, so use High.

    Copilot Fusion is generally available since October 28, 2026, in VS Code, the Copilot CLI, the Copilot app and JetBrains IDEs.

    There's no separate fee. High and Max can use more credits than Standard. Paid plans get 30% off Fusion through November 30, 2026.

    Fusion Max scored 60 on the Artificial Analysis Coding Agent Index, within 2 points of the top entry, at about half the cost and about 40% less time.

    Admins can exclude models from Fusion or make Fusion the default.

    You used Standard for a quick task, High for a review and compared High, Max and a single model. Next, you'll open the Jira Sprint Workbench.
